# NOVA-OS UIパターン流用調査書
| 項目     | 内容                    |
| :------- | :---------------------- |
| 文書番号 | ACV-FE-002              |
| 状態     | 提案（未実装）          |
| 調査対象 | NOVA-OS（読み取り専用） |
| 調査日   | 2026-09-09              |

## 1. 結論
NOVA-OSにある選択状態の可視化、操作要素のフォーカス表示、動作低減設定、狭幅時の操作部折返しは、agent-config-viewerへ取り込む。取込みは見た目だけの参照に留めず、agent-config-viewerの既存構造と淡色テーマに合わせて再実装する。

将来のコピー・移動も、NOVA-OSの擬似ファイルシステム実装を流用せず、許可済み設定ディレクトリだけを操作できる独立Featureとして取り込む。現行の閲覧機能に書込み操作は追加しない。

NOVA-OSのCSS/JavaScript本文は、ユーザー許可の範囲で取込み可能とする。`js/apps/file-manager.js`はC-05の採用元とし、必要な選択・操作フローをagent-config-viewer側のモジュールへ抽出する。ただし、`innerHTML`、LocalStorage、擬似ファイルシステム、作成・改名・削除の実装は安全要件に適合しないため、そのまま使用しない。

## 3. 実装候補の詳細
### C-01: ファイル選択の持続的可視化
- 状態: 実装済み。
- `preview.fileId` と一致する一覧ボタンを選択済みとして表示する。
- 色だけに依存せず、左罫線・太字・`aria-current="true"`を併用する。
- フォーカスと選択は別概念として扱い、Tab移動だけで選択状態を変更しない。

### C-02: 操作要素のフォーカス表示
- 状態: 実装済み。
- フォーカス意匠はグローバルな `button` 指定ではなく、`.catalog` に限定する。

### C-03: 動作低減設定
- 状態: 実装済み。
- 動作低減設定は新規アニメーション対象だけに限定し、既存の静的表示を変更しない。

### C-04: 狭幅レイアウト
- 状態: 実装済み。
- 320pxから768px幅で、プレビュー見出しと操作ボタンが重ならないことを確認する。

### C-05: Skill bundleの安全なパス移行
- 状態: Phase 2のread-only移行計画を実装済み。採用元ソースを `src/extensions/nova-file-manager.js` へ取り込み済み（未接続・未実行）であり、コピー・移動・参照更新は未実装。パス変更は必須要件として採用し、`SKILL.md`だけを単体移動する機能にはしない。
- Skill bundleは `.kiro/skills/<skill-name>/SKILL.md` を根とする同一ディレクトリ全体である。`references/`、`scripts/`、`assets/`、補助READMEなど、通常ファイルかつリンク・再解析ポイントではない配下エントリを対象とする。キャッシュ、バイナリ、非UTF-8、資格情報を含む可能性のある設定は、初期版の参照更新対象外とする。
- 移行前に、bundle内のUTF-8テキストから標準Markdown相対リンク、`#[[file:...]]`、明示的な`references/`・`scripts/`・`assets/`相対参照を検出する。実体へ解決できる同一bundle内参照だけを自動更新候補とし、URL、絶対パス、`~`始まり、親ディレクトリ遡行、実体なし、曖昧な平文参照は未更新として理由と行番号を表示する。
- 移行操作は、先に書込みなしの計画を作成して、移動前後のProvider相対パス、検出・更新・未更新・未解決件数、警告を表示する。自由入力パス、Provider横断、上書きは受け付けない。
- 初期の書込み操作は同一Provider内の非上書きコピーだけとする。移動は、コピー・参照更新・整合性検証・復旧ジャーナル・実行直前の再解析ポイント検証を完成させ、元・先・更新件数を明示確認した後に別Phaseで導入する。
- `js/apps/file-manager.js`からは、選択状態、操作列、フォルダ階層のナビゲーションフローを抽出して採用する。DOM生成は`innerHTML`ではなく既存の`createElement`・`textContent`・`replaceChildren`へ置換し、状態保存はLocalStorageではなくサーバー側の許可済みカタログを正本とする。作成・改名・削除の処理は採用しない。

詳細なbundle定義、参照分類、read-only計画Interface、将来のコピー・移動契約は `../design/ACV-DD-002_Skill_bundleパス移行詳細設計書.md` を正本とする。

## 4. 変更規模と段階
| 段階    | 対象                   | 主な変更箇所                                          | 規模   | リスク                             |
| :------ | :--------------------- | :---------------------------------------------------- | :----- | :--------------------------------- |
| Phase 1 | C-01〜C-04             | `browser-view.js`、`main.css`、既存E2E                | 小     | 表示・アクセシビリティの回帰       |
| Phase 2 | Skill bundle計画       | `server.py`、View、AppShell、E2E、設計・安全境界文書  | 大     | 参照誤判定、許可範囲逸脱           |
| Phase 3 | 同一Provider内のコピー | Phase 2に加え、非上書き、ステージング、検証、復旧記録 | 大     | 書込み失敗、競合、部分コピー       |
| Phase 4 | 同一Provider内の移動   | Phase 3に加え、明示確認、実行直前再検証、元の削除     | 大     | 元ファイル喪失、再解析ポイント競合 |
| Phase 5 | Provider間コピー・移動 | Provider境界、命名規則、競合解決、復旧方針            | 大以上 | 意図しない設定変更、復旧不能な競合 |

Phase 3以降は閲覧機能の拡張ではなく、ローカルファイル変更機能の新規導入として、詳細設計・安全境界レビュー・E2Eを満たし、実行前に明示承認を取得する。

## 5. 参照のみ・非採用の範囲
| 分類           | NOVA-OSの根拠                                                               | 判断理由                                                                                                                                             |
| :------------- | :-------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------- |
| 構造のみ参照   | `css/variables.css` のデザイントークン                                      | 将来のテーマ拡張時の整理方法として参照する。紫ネオン・半透明の値は導入しない。                                                                       |
| 構造のみ参照   | `css/windows.css` の見出しと操作列                                          | プレビュー見出しの情報階層だけを参照する。絶対配置のウィンドウ化はしない。                                                                           |
| 非採用         | `js/window-manager.js` のドラッグ・リサイズ・スナップ                       | ポインタ操作に偏り、キーボード操作・フォーカス管理・画面外配置を複雑にする。                                                                         |
| 取込み時に置換 | `js/apps/file-manager.js` の`innerHTML`、LocalStorage、作成・改名・削除実装 | ユーザー許可に基づき選択・操作フローは採用するが、DOM操作は安全なDOM APIへ、状態と書込み処理は許可範囲を検証するagent-config-viewer実装へ置換する。  |
| 非採用         | 外部フォント、カスタムカーソル、粒子・リップル演出                          | ネットワーク依存、可読性、性能、アクセシビリティの懸念がある。                                                                                       |
| 取込み許可     | NOVA-OS由来コード                                                           | ユーザー許可に基づき、必要箇所をagent-config-viewerへ取り込める。ただしC-05は書込み機能のため、実装前に詳細要件・安全境界レビュー・E2Eを完了させる。 |

## 6. 受入条件
### Phase 1
- プレビュー表示中は対応するファイル一覧項目が一意に判別できる。
- Tab操作でフォーカス位置が明瞭に表示され、タブの既存キーボード操作を損なわない。
- 動作低減を希望する環境で、新設した遷移・アニメーションを実質無効化する。
- 320px、768px、デスクトップ幅で操作部の横あふれがない。

### Phase 2以降
- 操作対象は許可済みProviderルート内のファイル・ディレクトリに限定される。
- コピーは既存ファイルを上書きせず、移動は実行直前の確認を経なければ実行できない。
- 失敗時に元ファイルを失わず、本文・認証情報を操作結果やログへ表示しない。
- HTML文字列を含む設定本文は、引き続き実行されずプレーンテキストとして表示される。

## 7. 検証方針
Phase 1では既存Playwright E2Eへ、選択中項目の属性、選択解除後の属性消去、HTML文字列の非実行を追加する。キーボード操作と動作低減設定は手動スモーク確認の対象とする。

Phase 2以降では、専用の一時HOMEで正常コピー、競合拒否、許可ルート外拒否、シンボリックリンク拒否、読取専用・書込み失敗時の元ファイル保全、移動確認のキャンセルをE2Eまたは統合テストで確認する。

## 8. 現時点の非対象
NOVA-OSのテーマ移植、ガラス効果、OSデスクトップ、複数ウィンドウ、ドラッグ・リサイズ、LocalStorage永続化、任意パス操作、設定本文の編集・作成・削除は対象外とする。コピー・移動はC-05として将来検討するが、本調査書では実装しない。
