# ローカルサーバー安全境界レビュー
## 1. 対象・結論
対象は`server.py`、`LocalConfigSource`、`Catalog`、`AppShell`、`BrowserView`である。ローカル閲覧専用という現在の要件に対し、固定許可範囲、不透明ID、読取直前の再検証、プレーンテキスト表示が一貫しており、本文プレビューを提供してよいと判断する。ACV-RV-001は旧フォルダ選択方式の設計レビューとして履歴を保持する。
## 2. 確認結果
| 観点             | 結果 | 根拠                                                                      |
| :--------------- | :--- | :------------------------------------------------------------------------ |
| 待受範囲         | 適合 | `ThreadingHTTPServer`は`127.0.0.1:8765`だけにbindする                     |
| 読取範囲         | 適合 | `Path.home()`配下の固定Provider rootと固定ホームファイルだけを走査する    |
| リンク回避       | 適合 | 走査・本文読取でシンボリックリンクとWindows再解析ポイントを除外する       |
| パス非露出       | 適合 | カタログは実パスでなくランダムなFile IDを返し、本文APIはIDだけを受け取る  |
| 本文再検証       | 適合 | ID、通常ファイル、許可root、2MiB、UTF-8を本文読取直前に確認する           |
| エラー露出       | 適合 | `read_failed`などの固定コードだけを返し、本文・絶対パス・生例外を返さない |
| DOM安全性        | 適合 | 本文を`<pre>.textContent`で表示し、HTMLとして解釈しない                   |
| Provider部分失敗 | 適合 | `ProviderResult`で失敗を分離し、他Providerの結果を維持する                |
## 3. 残余リスクと制約
- loopbackであっても、同じ端末・同じユーザー権限で接続できる別プロセスからの閲覧を防ぐ認証機構はない。本ツールは単一ユーザーのローカル利用を前提とし、共有端末・権限分離環境の保護境界には用いない。
- File IDはプロセス内カタログにだけ有効であり、新規カタログ生成またはサーバー再起動後は失効する。クライアントは`read_failed`として扱う。
- MarkdownのHTMLレンダリング、外部画像・リンクの読込、任意パス選択、編集機能は未実装であり、本レビューの対象外である。
## 4. 検証記録
Python構文検査、実ユーザーProviderカタログ、空HOME CLI、本文APIの一時HOMEスモーク検証、偽造ID拒否、2MiB超過拒否、変更ファイルの診断、`git diff --check`を実施した。実ブラウザでの手動スモーク確認は運用タスクとして残す。
